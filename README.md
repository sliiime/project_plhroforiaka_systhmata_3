## Εργασία 2

Σκοπός του δεύτερου σκέλους της εργασίας είναι η απάντηση σύνθετων ερωτημάτων που περιλαμβάνουν τις ζεύξεις που υλοποιήθηκαν στο 1ο σκέλος, φίλτρο με σταθερά και άθροισμα στήλης.

Η διαδικασία χωρίζεται στα εξής μέρη:
- Parsing
- Filtering on constants
- Filtering on equal columns
- Joins
- Summation


### Parsing

Σε αυτή τη φάση για την ανάγνωση των πινάκων και των ερωτημάτων χρησιμοποιείται ο parser που μας δώθηκε από το διαγωνσμό SIGMOD, με τις κατάλληλες αλλαγές, ώστε να χρησιμοποιεί τις δικές μας δομές αντί για της STL. Στο τέλος έχουν δημιουργηθεί τα κατάλληλα relations (πίνακες) και έχουν περαστει στη δομή Operation Manager που θα αναλάβει να εκτελέσει τα ερωτήματα.


### Filtering on constants

O Operation Manager δημιουργεί τη δομή Result η οποία περιέχει όλα τα IDs των γραμμών εκείνων που είναι ακόμα έγκυρα σύμφωνα με τα φίλτρα που έχουν εφαρμοστεί από το ερώτημα. Για να γίνει καλύτερα κατανοητή η αρχιτεκτονική Result η οποία φαίνεται παρακάτω:

![image](https://user-images.githubusercontent.com/27699969/206914264-78c680aa-b51b-4287-8305-ef3b838b8db0.png)

Η δομή result είναι υπεύθυνη για να κατασκευάζει τις στήλες που θα χρησιμοποιηθούν στα φίλτρα και στις ζεύξεις και για να αποθηκεύει σωστά το ενδιάμεσο αποτέλεσμα.

Για την ώρα χρησιμοποίεται μόνο το μέρος των Non-Joined relations. Αυτό που αξίζει να σημειωθεί έιναι πως το non-joined μέρος περιλαμβάνει Vectors ανεξάρτητα μεταξύ τους και διαφορετικών μεγεθών. Σε κάθε relation αντιστοιχεί ένα vector με τα έγκυρα IDs. Τα vectors αυτά αντικαθιστούνται με καινούργια καθώς εφαρμόζονται τα φίλτρα. Σε αυτή τη φάση χρησιμοποιείται η συνάρτηση FilterConstant.


### Filtering on equal columns

Όπως υποδείχτηκε, όταν γίνεται μία ζεύξη πάνω σε στήλες ίδιου πίνακα αρκεί να ελεγχθεί η ισότητα των τιμών στην ίδια γραμμή. Για αυτό χρησιμοιείται η συνάρτηση FilterPredicate η οποία όπως στο προηγούμενο στάδιο επιστρέφει μόνο ένα vector με έγκυρα IDs. Τα αποτελέσματα και πάλι αποθηκεύονται στο τμήμα των non-joined relations.


### Joins

Σε αυτό το στάδιο είναι που χρησιμοποιείται το τμήμα των joined relations. Αυτό περιέχει Vectors τα οποία είναι ίσου μεγέθους και παράλληλα. Για τη ζεύξη χρησιμοποιείται ένα wrapper class του πρώτου σκέλους της εργασίας το οποίο φτιάχνει ένα joint που περιέχει τα IDs των γραμμών που ταιριάζουν μεταξύ τους σε μορφή ενός vector από tuples. Αυτά τα ζεύγη περνάνε στο Result το οποίο θέτει τα IDs στο joined τμήμα κατάλληλα, με σκοπό να υπάρχει συνέπεια στην αλυσίδα των διαδοχικών joins.


### Join Sequence

Προκειμένου κάθε join να προσθέτει εως και μία καινούργια σχέση στο ενδίαμεσο joint table, και ακόμα πιο σημαντικά, για να γίνεται κάθε join που ζητήθηκε στο query, υλοποιήθηκε η συνάρτηση findJoinSequence. Στον αλγόριθμο που χρησιμοποιήθηκε στην findJoinSequence θεωρούμε ένα μη κατευθυνόμενο γράφημα όπου οι κόμβοι είναι τα relations και ένα edge μεταξύ δύο κόμβων είναι όλα τα μεταξύ τους joins. Ξεκινώντας μια Breadth first search αναζήτηση από κάποιον τυχάιο κόμβο, αν καλυφθούν όλες οι κορυφές του γράφου τότε βρήκαμε μια σειρά των joins που να πληρεί τις προϋποθέσεις που αναφέραμε παραπάνω, σε αντίθετη περίπτωση τα joins θα οδηγήσουν σε κενό result set. Κάθε φορά που επισκέπτεται κάποιος κόμβος προστίθονται όλες οι ακμές που συνδέονται με αυτόν τον κόμβο (δηλαδή όλα τα joins που χρησιμοποιούν αυτή τη σχέση) στο vector που καθορίζει την σειρά με την οποία θα γίνουν τα joins (sortedJoinsVector), ενώ παράλληλα προστίθονται στο toVisit Queue την άλλη σχέση του join (αν δεν είναι already visited) και η ακμή που μόλις χρησιμοποιήθηκε αφαιρείται από το γράφημα, έτσι ώστε όταν επαναληφθεί η ίδια διαδικασία από το relation που προστέθηκε στο Queue να μην προστεθούν δύο φορές ακμές (joins). Η διαδικασία αυτή επαναλαμβάνεται για κάθε κόμβο που υπάρχει στο toVisit queue μέχρις ότου το tοVisit queue να αδειάσει. Αν αδειάσει και δεν έχουν επισκεφθεί όλοι οι κόμβοι, τότε τα joins οδηγούν σε κενό result set, σε αντίθετη περίπτωση το sortedJoinsVector περιλαμβάνει μια σειρά απο joins με το επιθυμητό αποτέλεσμα.
